# 变更日志与版本号更新工作流

本文档记录了在本项目中进行代码提交前，更新版本号和生成变更日志的标准工作流程。本流程严格遵循 `version.md` 中的规范，确保 `package.json` 中的版本号始终作为唯一真值源。

## 前置要求

- 确保你的本地工作区已完成所有相关的代码修改或功能开发。
- 明确了解本次提交的变更类型（`feat`, `fix`, `refactor`, `docs`, `chore` 等）。

## 标准流程

在每次提交 (Commit) 之前，必须执行以下三个步骤：

### 步骤 1: 运行版本更新脚本

根据本次提交的变更类型，在项目根目录运行对应的 npm 脚本，安全地递增版本号。该操作会自动更新 `package.json` 和 `package-lock.json` 中的 `version` 字段，且不会自动创建 git tag。

- **如果是新增功能、重构或删除类变更 (`feat` / `refactor` / `remove`):**
  ```bash
  npm run version:minor
  ```

- **如果是修复、文档、样式或日常维护类变更 (`fix` / `docs` / `ui` / `chore` / `test`):**
  ```bash
  npm run version:patch
  ```

> ⚠️ **注意**: 如果是重大架构重构导致的不兼容变更，需要手动递增 MAJOR 版本号（如 `npm version major --no-git-tag-version`）。

### 步骤 2: 补充变更日志 (version.md)

1. 运行变更日志生成脚本（此脚本目前在本地可用，如果没有，请手动在 `version.md` 顶部插入模板）。
   ```bash
   npm run changelog
   ```
2. 按照命令行提示回答关于类型、作用域和简要说明的问题。
3. 打开根目录的 `version.md`，在文件顶部的历史记录之前（通常在“版本号更新工作流”说明之后），找到刚刚插入（或手动插入）的变更模板。
4. **填写真实内容**: 必须确保填写的变更日志实事求是，与本次提交的代码修改强相关。
   - **类型 (type)** 和 **范围 (scope)** 必须填写。
   - **说明**: 用一段话概括核心变更。
   - **实现细节**: 分点列出主要的代码改动和逻辑变更。
   - **文件变更**: 列出主要修改、新增或删除的文件。
   - **改进效果**: 简述此次提交带来的价值。
   - **影响范围**: 说明变更影响的功能模块。

**模板示例:**

```markdown
---

VX.Y.Z type(scope): 简要描述

类型: type

范围: scope

说明:
详细说明本次提交的核心目的和主要解决的问题。

实现细节:
1. **模块A调整**
   - 具体的代码改动说明。
2. **模块B新增**
   - 具体的代码新增说明。

文件变更:
修改文件:
- `/path/to/file1`
- `/path/to/file2`

改进效果:
- 带来的性能提升、体验优化或问题修复。

影响范围:
- 受影响的页面或业务逻辑。

---
```

### 步骤 3: 暂存与提交 (git add & git commit)

确认 `package.json`、`package-lock.json` 和 `version.md` 的版本号完全一致后，将文件加入暂存区并提交。

1. **暂存文件**：
   将你的业务代码文件以及三个版本控制相关文件一起添加到暂存区。
   ```bash
   git add package.json package-lock.json version.md <其他你修改的文件>
   ```

2. **提交代码**：
   使用规范的 Commit Message 格式进行提交。格式必须为：`VX.Y.Z type(scope): 简要描述`。
   ```bash
   git commit -m "VX.Y.Z type(scope): 简要描述"
   ```
   *注意：这里的版本号和描述必须与你在 `version.md` 中填写的一致。*

## 常见场景拆分提交

如果你一次性做了很多不相关的修改，**强烈建议分批次提交**。
对于每一批次的提交，都需要重复上述的 **1 -> 2 -> 3** 的完整流程。
例如：
1. 第一批次：提交基础设施配置 -> 走一次版本递增 + 补充日志 + git add & commit。
2. 第二批次：提交文档说明 -> 再走一次版本递增 + 补充日志 + git add & commit。
